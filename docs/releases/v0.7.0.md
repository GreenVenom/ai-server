# M07 Closeout: Obsidian Retrieval V2 Cutover

- **Status:** Complete and accepted
- **Closeout date:** 2026-07-27
- **Release scope:** Production cutover of the `personal-knowledge` Obsidian
  retrieval workload from the V1 index to the independently rebuilt V2 index.
- **Decision record:** [ADR-0022](../adr/ADR-0022-obsidian-index-v2-cutover-and-v1-rollback-retention.md)

## Outcome

`obsidian_chunks_v2` is the live Qdrant collection for the
`personal-knowledge` vault. The production indexer, scheduled LaunchAgent,
MCP adapter, and OpenClaw Obsidian plugin all target the V2 collection and its
separate manifest root, `data/obsidian/manifests-v2`.

The pre-cutover V1 collection and manifest remain unchanged as a rollback
target for the retention period defined in ADR-0022.

## Delivered

- Built and accepted `obsidian_chunks_v2` as the live retrieval collection.
- Moved the active manifest to
  `data/obsidian/manifests-v2/personal-knowledge.json`.
- Updated the production sync/index scheduler to use V2 explicitly.
- Updated the MCP retrieval adapter and OpenClaw Obsidian plugin source to use
  V2.
- Updated operational health, status, backup, and integrity scripts for the
  active V2 configuration.
- Corrected reconciliation so it validates manifest chunk IDs against Qdrant
  point IDs rather than treating all mirrored Markdown as indexable.
- Added ADR-0022 to record the cutover, rollback contract, and retention
  policy.

## Operational State

- The hourly `ai.openclaw.obsidian-sync-index` LaunchAgent is loaded and uses
  the V2 manifest root.
- `check-obsidian.sh` verifies the job state, live manifest, mirror, source
  commit state, LaunchAgent, and exact manifest-to-Qdrant chunk-ID
  reconciliation.
- The V1 collection and original manifest must not be modified during the
  retention period.

## Rollback and Retention

Retain `obsidian_chunks_v1`, the original manifest root, and the saved
pre-cutover runtime configuration for at least 30 days after 2026-07-27.

If rollback is required, restore the saved runtime configuration, repoint the
scheduler, MCP adapter, and plugin to V1, rebuild the plugin if needed, and
rerun the scheduler, `check-obsidian.sh`, MCP adapter check, and
`openclaw mcp doctor`. The retained V1 collection is read-only recovery data;
do not reindex into it.

After the retention date, remove V1 only through a separately recorded cleanup
decision that confirms V2 remains healthy and recoverable.

## Handoff to M08

M08, Backup and Disaster Recovery, can begin without waiting for the V1
retention period to expire. M08 should treat the retained V1 index and manifest
as rollback data, while validating backup and restore coverage for the active
V2 collection, V2 manifest root, production configuration, and scheduler
state.
